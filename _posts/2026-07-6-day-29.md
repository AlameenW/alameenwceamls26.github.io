what_i_learned: |
  Spent the entirety of today on the FastAPI application — the web interface that will eventually serve our trained damage classification model to end users.
  Started by configuring the API routes that the frontend would call, then wrote the core functionality to serve the HTML to the frontend and handle image loading and processing on the backend. Getting the routing structure   right early matters, a clean backend architecture makes everything that comes after easier to build and debug.
  From there I moved to the frontend and put together a simple UI to illustrate and test the full app workflow. Nothing polished at this stage, just functional enough to walk through the end-to-end process — a user uploads    a building image, the app processes it, and a damage classification comes back.
  To test the pipeline without waiting on the actual trained model, I created a dummy model and loaded it using ONNX. Running the app end to end with the placeholder model was an important step — it confirmed that the         workflow is sound and the integration points between the frontend, backend, and model are all behaving as expected.
  Tomorrow the focus shifts to improving the UI and swapping the dummy model out for the real one we have trained. The core plumbing is in place, which puts us in a good position heading into the final stretch of the          program.
